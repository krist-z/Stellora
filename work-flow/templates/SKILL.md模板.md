# Skill / Playbook Name

## Purpose

使用本 skill 完成 `<task/domain>`。本 skill 只保留跨项目、跨用户可复用流程；项目专属路径、命令、验收入口、业务规则和密钥边界应读取当前项目的 Agent 入口文档、项目规则和 docs。

## Quick Start

1. 确认用户请求是否匹配本 skill 的触发范围。
2. 读取当前项目 Agent 入口文档和必要规则文件。
3. 选择最小可行流程。
4. 使用本 skill 的 scripts / references / assets 时，只加载当前任务需要的部分。
5. 完成后按项目规则验证和收尾。

## Workflow

### 1. Intake

- 明确用户要的产出。
- 明确是否允许改文件、运行命令、访问外部服务。
- 明确任务等级和风险等级。
- 明确当前项目是否有更高优先级规则。

### 2. Explore

- 读取项目入口和相关文件。
- 使用快速搜索工具定位。
- 如果需要参考资料，只读取 `references/` 中相关文件。

### 3. Plan

- 低风险任务可直接执行。
- 高风险任务先输出计划并等待确认。
- 涉及发布、删除、迁移、权限、敏感数据、外部系统写入时必须先确认。

### 4. Execute

- 优先使用项目已有脚本和 helper。
- 如果本 skill 提供 deterministic script，优先运行脚本而不是重写大段代码。
- 保持改动局部，遵守项目边界。
- 不写入真实密钥、个人数据或私有路径。

### 5. Validate

- 使用当前项目的验证命令。
- 如果本 skill 有独立校验脚本，可作为补充，但不能替代项目验收。
- 记录 PASS / FAIL / WARN 和未覆盖项。

### 6. Close Out

- 按项目 Agent 入口文档汇报改动文件、验证命令、风险和下一步。
- 如果改变长期结论，更新项目文档或证据。
- 如果存在残余风险，明确说明。

## Resources

按需保留这些目录；不需要就删除。

```text
skill-name/
├─ SKILL.md
├─ scripts/
├─ references/
└─ assets/
```

### scripts/

适合放：

- 重复运行的 deterministic 操作。
- 校验脚本。
- 转换脚本。
- 生成模板的脚本。

脚本必须经过实际运行验证。脚本不得默认执行高风险写入、删除、发布或外部系统修改。

### references/

适合放：

- 较长 API 文档摘要。
- 领域术语。
- schema。
- 复杂流程说明。
- 安全和合规约束。

`SKILL.md` 中只写“什么时候读哪个 reference”，不要把全部内容塞进主文件。

### assets/

适合放：

- 模板文件。
- 示例工程。
- 图片、字体、静态资源。
- 会被复制或改造成输出的材料。

不得放真实密钥、真实客户数据、私有账号信息或受限素材。

## Safety Rules

- 不覆盖项目规则。
- 不自动提交、推送、发布、删除或迁移。
- 不安装高权限工具或后台服务，除非用户明确要求。
- 不访问外部系统写接口，除非用户明确授权。
- 不在文档或输出中泄露凭据。
- 涉及敏感数据、生产、权限、财务、医疗、法律等场景时，要求人工确认。

## When Not To Use

不要在这些情况下使用本 skill：

- 当前项目 Agent 入口文档已明确给出更具体流程。
- 任务只是一次性小改，不需要本 skill 的专门知识。
- 用户请求涉及高风险副作用，但没有明确授权。
- 本 skill 会诱导创建 issue、提交、推送、安装 hook、访问外部服务，而用户没有要求。
