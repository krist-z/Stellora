# AI 工作流搭建文档索引

本文档目录是一套通用 AI 协作工作流说明，适用于不同 AI 助手、不同 IDE、不同代码代理和不同项目类型。它不绑定某个具体工具；如果使用的 AI 支持规划模式、计划模式、任务模式或自定义人格风格，可以让 AI 先阅读本文档，再按个人偏好做轻量改写。

这套文档的目标是把“提出需求、澄清目标、读取规则、执行改动、验证结果、同步证据、控制风险、交接下一步”变成任何项目都能复用的闭环流程。

## 文档目录

| 路径 | 用途 |
|---|---|
| `full-closure/全量化工作流搭建说明.md` | 完整闭环版，覆盖项目设计、执行、验证、文档同步、安全、回滚、审计和长期维护。适合复杂功能、跨模块改动、生产风险、发布、迁移和高可信交付。 |
| `agile/敏捷开发工作流搭建说明.md` | 敏捷轻量版，从完整闭环中抽取日常开发最需要的步骤。适合小功能、bug 修复、局部文档、脚本调整和快速迭代。 |
| `templates/AGENTS.md模板.md` | Agent 入口文档模板。可命名为 `AGENTS.md`、`AI_GUIDE.md`、`.ai/guide.md` 或团队约定的任意名称，用来告诉 AI 当前项目的规则、边界、验证入口和收尾要求。 |
| `templates/project_rules.md模板.md` | 项目规则模板，用来固化架构边界、编码规范、提交边界、脚本规则、文档规则、安全规则和验证规则。 |
| `templates/SKILL.md模板.md` | Skill 能力包模板，用来创建可触发、可复用、上下文友好的 AI 专项技能。不同 AI 平台也可称为 tool guide、capability、playbook 或 workflow card。 |
| `templates/MCP配置说明模板.md` | MCP 或其他工具服务器的配置说明模板，覆盖用途、权限、密钥、安全边界和验证方式。 |
| `references/通用工作流补充清单.md` | 补充清单，列出常见遗漏项、安全增强点、质量门禁、风险分级和可选成熟度路线。 |

## 推荐使用方式

1. 新项目先复制 `templates/AGENTS.md模板.md`，改成项目自己的 Agent 入口文档。
2. 项目开始长期维护时，再复制 `templates/project_rules.md模板.md`，补齐工程规则和安全边界。
3. 日常小任务使用 `agile/敏捷开发工作流搭建说明.md`。
4. 复杂任务、跨模块改动、发布、迁移、数据删除、安全相关任务，使用 `full-closure/全量化工作流搭建说明.md`。
5. 某类任务反复出现时，使用 `templates/SKILL.md模板.md` 创建通用 skill 或团队 playbook。
6. 需要接入文件系统、命令行、浏览器、知识库、数据库、项目管理系统等外部工具时，使用 `templates/MCP配置说明模板.md` 记录权限和安全边界。

## 给任意 AI 的使用提示

可以把下面这段交给任意 AI：

```text
请先阅读这套 AI 工作流文档。不要直接照搬其中的所有流程，请先进入规划/计划模式，根据我的项目规模、风险等级、技术栈、个人工作习惯和工具环境，生成一份适合我的轻量配置方案。优先保证安全、可验证、可回滚、可交接。除非我明确要求，不要执行提交、推送、发布、删除、迁移、安装高权限工具或访问外部系统。
```

如果 AI 支持个人风格配置，可以继续补充：

```text
请在不降低安全和闭环质量的前提下，把工作流调整为我喜欢的风格：例如更简短、更严格、更敏捷、更适合独立开发、更适合团队协作，或更适合产品/设计/研究类项目。
```

## 一个实用原则

完整工作流不是每次都要执行的重流程。它是一套“风险越高，证明越强”的工具箱。敏捷工作流则是从工具箱里挑出日常最常用的一小组动作，让小任务保持轻快，但不丢掉边界、验证、安全和交接。
